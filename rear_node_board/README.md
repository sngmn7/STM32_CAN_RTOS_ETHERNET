# REAR NODE BOARD — STM32F446RET6 ×2

Rear 존의 말단 두 노드를 **한 장의 PCB**로 합친 보드.
H723 존 컨트롤러는 **Nucleo-144 모듈 그대로** 두고 J2 로 연결한다.

```
[H723 Nucleo-144]  ── J2 (CAN 로직신호 4 + GND) ──┐
                                                   │
   ┌───────────────── REAR NODE BOARD ─────────────┴──────────────┐
   │  U3 ─ CAN500 ─ U4 ─ U1 (F446RET6, rear body)                 │
   │  U5 ─ CAN250 ─ U6 ─ U2 (F446RET6, 센서/램프 노드)             │
   │                        └ LED×4, 스위치, HC-SR04, BNO085      │
   └──────────────────────────────────────────────────────────────┘
              │
        J5 ── REAR-CAN-H 500k → 모터 노드(외부)
```

**검증 상태**: ERC **0 errors / 0 warnings**, 배치검사 통과,
두 MCU **각각 64/64 핀 전부 연결**(미연결은 트랜시버 Vref ×4, 의도된 NC).

### 배선 방식

**436개 배선 + 51개 정션**으로 실제 선이 그려져 있다. 라벨만 띄워놓은 게 아니다.

| 실선으로 그린 것 | 방식 |
|---|---|
| CAN 500k / 250k 버스 | 세로 트렁크 + 각 노드로 가지 + 정션 |
| 종단 5세트 | JP→60R→중점→60R→CANL 직렬 체인, 중점에서 4.7nF→GND |
| LED 4개 | 저항→애노드 실선, 캐소드→GND |
| 크리스탈 2개 | 크리스탈↔로드캡 실선, 캡→GND |
| 스위치 + 풀업 | 같은 노드로 실선 결선 |
| 디커플링 15개 | 위쪽 +3V3 레일 / 아래쪽 GND 레일 실선 + 정션 |

**MCU 두 개만 네트 라벨을 쓴다.** 핀 128개를 시트 전체로 배선하면 오히려
읽을 수 없어지기 때문이고, 이건 실무 회로도의 표준 방식이다.
전기적 연결은 동일하며 네트리스트로 검증했다.

### ★ 네트 라벨 = 실제 배선이다

**PCB 는 회로도의 선 그림을 보지 않는다. 네트리스트만 읽는다.**
그래서 라벨로 연결하든 선으로 연결하든 PCB 결과는 완전히 같다.

이것을 말이 아니라 실물로 확인했다 — 이 회로도에서 PCB 를 실제로 생성했다.

```
netlist : 83 components, 136 nets
placed  : 83 footprints        <- 누락 0
nets    : 136 on board, 404 pads assigned
DRC     : 0 violations, 266 unconnected items
```

`266 unconnected items` 가 바로 **rats nest** 다. pcbnew 가 "이 266 개를
연결해야 한다"고 인식했다는 뜻이고, 곧 MCU 핀을 포함한 모든 연결이
정상적으로 넘어갔다는 증거다.

예를 들어 U2(F446) 의 핀들은 PCB 에서 이렇게 이어진다.

```
pin 11  TOGGLE_SW  -> R18.2, SW1.1
pin 14  LED_LEFT   -> R14.1
pin 30  ND_VCAP1   -> C27.1
pin 44  ND_CAN_RX  -> U6.4
pin 61  I2C1_SCL   -> J8.3, R19.2
pin  2  ND_PC13    -> J14.1
```

**64 핀 전부가 이런 식으로 연결돼 있다.**

## 1. 왜 F446 두 개인가

원래 rear body 노드는 F407VG(LQFP100)였지만 F446RET6(LQFP64)로 통일했다.

| | 통일 전 | 통일 후 |
|---|---|---|
| MCU 종류 | F407VG + F446RE | **F446RE ×2** |
| 풋프린트 | LQFP100 + LQFP64 | **LQFP64 ×2** |
| 지원회로 | VCAP 2개 + 1개, 서로 다름 | **완전 동일** |
| BOM 라인 | 2 | **1** |

> ⚠️ **펌웨어 이식 필요**: F407 rear body 펌웨어는 CAN1 이 **PD0/PD1** 이었다.
> F446 LQFP64 에는 그 핀이 없어 **PA11/PA12** 로 옮겨야 한다.
> 현재 rear body 는 500k ping/echo(0x101→0x181)만 하므로 이식 부담은 작다.

## 3. ★ 종단 점퍼 — 이것만은 틀리면 안 됨

| 버스 | 드롭 | 점퍼 | 기본 |
|---|---|---|---|
| REAR-CAN-H 500k | **3개** (H723, U1, 모터노드) | JP1 (H723) | **삽입** |
| | | JP2 (U1, 버스 중간) | **개방** |
| | | JP3 (모터노드 쪽) | **삽입** |
| REAR-CAN-L 250k | 2개 | JP4, JP5 | **둘 다 삽입** |

3개를 다 끼우면 40 Ω 이 되어 드라이버가 규정 차동전압을 못 만들고 통신이 깨진다.
종단은 스플릿(60 Ω + 60 Ω, 중점 4.7 nF → GND) 방식.

## 4. 조립 시 반드시 지킬 것

**① C26 / C27 (VCAP, 각 MCU 30번핀) — 필수**
내부 레귤레이터 안정화용. 없거나 멀면 **칩이 아예 부팅하지 않는다.**
디커플링처럼 "있으면 좋은" 부품이 아니다. 핀 바로 옆에 배치할 것.

**② R2 / R3 (BOOT0 풀다운, 각 60번핀) — 필수**
빠지면 플래시 부팅이 안 되고 무작위로 시스템 부트로더로 들어간다.
커스텀 보드 첫 제작에서 가장 흔한 실패 원인.

**③ SWD 헤더에 NRST 포함**
클럭 설정을 잘못 넣었을 때 connect-under-reset 으로만 살릴 수 있다.
NRST 가 없으면 그대로 벽돌이 된다.

**④ VDD 핀마다 100 nF**
MCU 하나당 VDD 4개(19, 32, 48, 64) → 각각 바로 옆에.

**⑤ J2 의 GND 를 반드시 연결**
H723 Nucleo 는 자기 전원을 쓰지만, 트랜시버가 기준 전위를 공유해야
CAN 이 성립한다. GND 미공통이 CAN 무응답의 가장 흔한 원인이다.

---

## 5. 펌웨어 쪽 확인 사항

**클럭을 HSE 로 바꿔야 한다.**
현재 F446 펌웨어 `SystemClock_Config()` 는 HSI 를 쓴다
(`RCC_OSCILLATORTYPE_HSI`, PLLM=16, PLLN=336, PLLP=4 → 84 MHz).

STM32F4 의 HSI 는 25 °C 에서 ±1 %, 온도 범위 전체로는 더 나빠진다.
CAN 은 통상 **±0.5 % 이하**를 요구하므로 HSI 로는 마진이 없다.
Nucleo 로 책상에서 짧은 배선일 때는 돌아가지만, 실제 배선이 길어지면
마진이 사라진다. **Y1/Y2 를 달았으니 HSE 로 전환할 것.**

---

## 6. PCB 뜰 때

- **2층으로 충분하다.** 최고 속도가 CAN 500 kbps 라 임피던스 제어·길이 매칭 불필요
- 바텀은 통 GND 플레인
- **CANH/CANL 은 반드시 쌍으로 나란히**, 트랜시버→커넥터 스터브 최소화
- LQFP64 는 0.5 mm 피치 — 이것만 주의
- HC-SR04 는 5 V 라 J7 전원만 5 V 레일에서 따온다

## 8. 재생성

```bash
# 회로도 + ERC + 네트리스트 + BOM + PDF
python tools/build.py

# 네트리스트 -> PCB (풋프린트 전부 로드 + 네트 할당 + 개략 배치)
"E:\Program files\bin\python.exe" tools\make_pcb.py rear_node_board
```

회로 수정은 `tools/gen_rear_board.py` 에서. KiCad GUI 에서 직접 고치면
다음 빌드에 덮어써진다.

> `make_pcb.py` 는 **레이아웃 시작점**을 만들어 줄 뿐이다. 부품은 격자에
> 대충 뿌려져 있으니 pcbnew 에서 배치를 정리하고 라우팅하면 된다.
> 이미 만든 배치를 유지하려면 다시 돌리지 말고, 회로도를 고친 뒤
> pcbnew 의 **"회로도에서 PCB 업데이트"** 를 쓰는 편이 낫다.
